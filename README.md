# График смен

Интерфейс планирования смен сотрудников на Next.js App Router, React и TypeScript.

- [Демоверсия на MySQL](https://rm.pyshnet.ru)
- [Swagger UI](https://rm.pyshnet.ru/docs)

## Запуск

Нужны Node.js 22.13+ и pnpm 10.

```bash
pnpm install
pnpm dev
```

Откройте http://localhost:3000. Без настроек приложение запускается в деморежиме с восемью сотрудниками и тремя шаблонами. Сохранение создаёт отдельный график для браузера и записывает его в локальную базу SQLite в каталоге `.data/`.

## Работа с графиком

- Переключайтесь между неделей и месяцем. Стрелки меняют период, а по нажатию на его название можно выбрать неделю или месяц. Кнопка «Сегодня» в календаре возвращает к текущей дате.
- Поиск принимает имя, фамилию или их части в любом порядке.
- Нажмите на одну или несколько ячеек и выберите шаблон или укажите своё время. Клавиши 1–9 применяют соответствующие шаблоны, Escape снимает выделение.
- Значок карандаша или двойной клик открывает редактирование назначенной смены. В диалоге можно удалить смену. Кнопка «+» добавляет шаблон, а кнопка с номером открывает его редактирование.
- В окне шаблона можно выбрать готовый цвет, оттенок из палитры или произвольный цвет через системный диалог.
- Покрытие показывает количество сотрудников со сменами в каждый день. Часы у сотрудника суммируются за видимый период. Время окончания раньше начала считается переходом через полночь.
- «Сохранить» записывает черновик. «Опубликовать» одновременно сохраняет черновик и фиксирует опубликованную версию. При конфликте версий сервер отклоняет перезапись.

### От загрузки до сохранения

1. Серверная страница проверяет доступ и передаёт редактору первую страницу сотрудников и смены за текущую неделю по московскому времени. Поиск, пагинация и смена периода используют тот же репозиторий через `GET /api/schedule/employees`.
2. Редактор хранит правки по ключу `сотрудник/ГГГГ-ММ-ДД`. Для каждой ячейки он запоминает исходную смену и итоговое значение. Это позволяет пересчитать покрытие сразу и восстановить правки при возврате к другой неделе или странице. `null` означает удаление смены.
3. При сохранении клиент передаёт все накопленные правки, текущий список шаблонов и ожидаемую версию графика. Сервер валидирует запрос и проверяет версию под блокировкой строки графика. Изменения смен, шаблонов и версии фиксируются одной транзакцией.

Аватары сотрудников обрабатываются через Sharp. Загруженное изображение приводится к размеру 192 × 192 и хранится в поле сотрудника как WebP data URL. Изменение или удаление аватара сохраняется вместе с карточкой.

### Совместимость данных

Репозиторий использует номер версии нормализованных таблиц, чтобы распознать черновик, изменённый старым релизом. Обычное чтение графика использует согласованный снимок БД, а перенос черновика из JSON выполняется под блокировкой. При редактировании смен JSON обновляется внутри БД для совместимости с предыдущими релизами. Стоимость этой операции зависит от размера черновика.

В поле цвета хранятся идентификаторы готовых цветов (`blue`, `violet`, `green`, `amber`) или HEX в формате `#RRGGBB`. Существующие значения читаются как раньше. Для редактирования графика с HEX-цветами нужна версия с поддержкой палитры.

### Чат поддержки

Браузер отправляет сообщения через Server Action и опрашивает `GET /api/support-chat` с токеном беседы. Сервер пересылает сообщения в WebSocket-релей, заданный через `VISITOR_WEBSOCKET_URL`, и сопоставляет ответы по коду беседы. История хранится в памяти процесса. Беседа истекает через 30 минут без новых сообщений, а перезапуск процесса очищает историю.

## PostgreSQL, MySQL и Auth.js

Скопируйте `.env.example` в `.env.local`, задайте секрет Auth.js, пароль менеджера и адрес приложения в `AUTH_URL`. Укажите адрес существующей базы в `DATABASE_URL`.

| База | Формат адреса |
| --- | --- |
| PostgreSQL | `postgresql://user:password@host:5432/schedule` |
| MySQL | `mysql://user:password@host:3306/schedule` |

Приложение выбирает драйвер по схеме адреса. Если логин или пароль содержит специальные символы URI, закодируйте их по отдельности перед подстановкой. Учётной записи базы нужны права CREATE, SELECT, INSERT, UPDATE, DELETE и REFERENCES в схеме приложения.

Версия схемы 1 создаёт реляционные таблицы сотрудников, смен и шаблонов при первом обращении. Исходные данные для миграции берутся из `schedule_workspaces.draft`. При публикации текущий черновик копируется в опубликованный снимок.

Сервер выполняет поиск по ФИО и пагинацию по 25 сотрудников в SQL. Страница сотрудников загружает только карточки, а график запрашивает смены и покрытие за выбранную неделю или месяц. Покрытие учитывает всех сотрудников. Уникальность пары сотрудник–дата внутри графика задаёт первичный ключ таблицы смен. Смены связаны с сотрудниками внешним ключом.

При заданном `DATABASE_URL` вход выполняется по паролю менеджера. Auth.js выдаёт сессию для рабочего графика менеджера.


Тесты проверяют расчёт смен и покрытия, валидацию, миграцию старого графика, сохранение и публикацию, а также SQL-поиск и пагинацию. По умолчанию интеграционные сценарии используют SQLite в памяти. ## Документация API

Swagger UI доступен по пути `/docs`, OpenAPI JSON — по пути `/api/openapi`. Описан REST-маршрут `GET /api/schedule/employees`, включая параметры, формат ответа и ошибки. На стенде с MySQL или PostgreSQL перед запросом из Swagger войдите через `/login` на том же домене.

Маршрут принимает `query`, `page` и пару дат `from` и `to`. Диапазон включает обе даты и ограничен 31 днём. Если даты опущены, сервер возвращает текущую неделю. Поиск ограничивает список сотрудников и их смены, а покрытие считается по всему графику за тот же период.
